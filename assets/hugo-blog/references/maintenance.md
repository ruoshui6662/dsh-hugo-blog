# Maintenance（日常维护）

本文件只供 `hugo-blog` Skill 的巡检与维护分支使用；路由与流程见 `SKILL.md`。

## hugo list 五种 kind 的用途

`hugo_list` 按 kind 返回不同集合，巡检时先按目标选 kind，不要全量拉回再人工筛：

- `drafts`：`draft: true` 的草稿，用于起草进度与待发布盘点。
- `future`：`publishDate` 在未来的文章，用于定时发布巡检。
- `expired`：已过 `expiryDate` 应下架的文章，用于定时下架巡检。
- `regular`：已发布普通文章，用于抽查 front matter 与链接健康度。
- `all`：全部内容，仅在需要全量盘点时使用。

## 定时发布/下架巡检节奏

- 建议每周至少巡检一次 `future` 与 `expired`：到点的文章应改 `draft`/日期并走发布流程，已过期的文章应确认下架。
- 巡检动作：`hugo_list` 列清单 → 对每篇用 `hugo_edit_frontmatter` 调整 → `hugo_build_check` → 用户确认 → `hugo_publish`。不要批量静默发布。
- 路由用户说“巡检一下定时要发的文章”时，先交付清单与每篇的建议动作，等用户确认后再改。

## Front matter lint 常见问题

- 缺 `title` 或 `date`：新建文件未补字段，列表与 RSS 排序会异常。
- `draft` 与 `publishDate` 矛盾：草稿状态下设了发布时间，巡检时先确认意图再改。
- 日期格式非 RFC3339：如 `2026/11/05`，改为 `2026-11-05T07:00:00+08:00` 形式。
- taxonomy 未在站点配置声明：`tags`/`categories` 写了但不生成分类页，先补配置再改文章。
- `aliases` 与现有路径冲突：改名后旧路径仍被新文章占用，巡检时核对。
- `params` 字段名拼写与主题不一致：以同目录已有文章为准。

## 断链与孤儿图的人工检查清单

- 文章内相对链接（bundle 图片、站内引用）：逐篇打开渲染结果，确认目标文件存在。
- `static/` 图片：确认被至少一篇文章引用；长期无引用的图片列为孤儿图候选，先向用户确认再删除。
- 改名或改路径后：检查 `aliases` 是否覆盖旧 URL，站内旧链接是否已更新。
- 外部链接：抽查可达性，失效链接优先更新或加注，不要静默删除正文事实。
- 检查频率可随巡检节奏，不必每次发布都全量扫。
